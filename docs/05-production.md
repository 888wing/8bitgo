- **要回答的問題：**
  1. 第一天投票時，玩家有沒有感到「這一票好重」？
  2. 玩家說得出某位陪審員 **為甚麼** 改變主意嗎？
  3. 蓋章是在做判斷，還是在做功課？
  4. 第二天截電通知出現時，玩家會不會主動翻回第一天改印章？

## 2. 內容格式

一個案件 = 五張表：

| 表 | 每一行是 | 欄位 |
|---|---|---|
| 證人 | 一個證人 | 日子、哪一方、證詞、兩三個關鍵說法、帶出的證物 |
| 說法 | 一個關鍵說法 | 誰說、支持或削弱哪一環、會不會被剔除 |
| 理由 | 一組對照 | 說法 × 證物或另一個說法、批註全文、頁邊短句（一行寫得完）、作用、哪一席才看得到 |
| 陪審員 | 一位陪審員 | 預設蓋章規則、翻不動的格子、跟大隊的程度、習慣、秘密 |
| 證據鏈 | 一個環 | 哪些說法支持它、是否必要 |

AI 陪審員的格子大部分由「預設蓋章規則」產生（例如「信警察」「只信物證」），只有關鍵的格子手寫。寫劇本的人填表，程式不用改。

桌面版另外要畫：每件證物的原大圖和兩倍圖，並標出每個細節在證物上的位置（見 [06 §6](06-art.md#6-人物和證物)）。

## 3. 技術

- 遊戲用 Godot 4.7（GDScript，Compatibility 渲染器），桌面和網頁版同一份程式（[決策 14](decisions.md)）。分支對白日後可以加 Ink 的 Godot 外掛。
- 規則（印章、黑板、表決）寫成不依賴畫面的純邏輯。JS 版（`prototype/engine.js`）給文字原型和平衡模擬用，可以跑上千場模擬評議來檢查平衡；Godot 版（`game/scripts/rules/rules.gd`）由它移植，`npm run test:godot` 重播 JS 版的 40 局、約八千步，回傳值和狀態逐項相同。兩邊的案件資料都來自 `prototype/case.js`。
- 美術由 `art/src/` 的程式畫法輸出成 PNG 給 Godot（`npm run bake`）；字用瀏覽器壓好的點陣字表，遊戲本身不用連網，也不帶字型檔（[決策 15](decisions.md)）。
- 自動試玩：`npm run check` 匯出網頁版，用真的滑鼠和觸控事件玩第一天。網頁版（Phaser 3.90）的手感切片最後一版在 commit `3a3a819`。

## 5. 未決定的事

1. **法庭節奏：** 證詞自動推進，還是逐句按鍵？
2. **世界觀：** 受八十年代香港啟發的虛構城市，還是完全架空？
3. **對白：** 粵語口語，還是書面語？
4. **平台：** PC 優先，還是手機？桌面版是橫向的，手機要橫放；要直向的話，版面要另外設計。
5. **路線：** 第一周目是否固定第七席？
6. **正式美術：** 自己畫，還是找美術？風格定稿圖的第一版（[06 §10](06-art.md#10-風格定稿圖第一版)）可以當作給美術的樣板。
