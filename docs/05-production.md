# 05 製作

## 1. 原型：先驗證核心

- **範圍：** 簡化的序幕，加第一、二天；純文字；不做美術，也不做夜晚。
- **要有的：** 四個證人、約十個說法、蓋章、對照（約五組理由）、黑板（六個 AI 陪審員）、四個評議動作、不記名投票、五票即決。
- **要回答的問題：**
  1. 第一天投票時，玩家有沒有感到「這一票好重」？
  2. 玩家說得出某位陪審員 **為甚麼** 改變主意嗎？
  3. 蓋章是在做判斷，還是在做功課？
  4. 第二天截電通知出現時，玩家會不會主動翻回第一天改印章？

## 2. 內容格式

一個案件 = 五張表：

| 表 | 每一行是 | 欄位 |
|---|---|---|
| 證人 | 一個證人 | 日子、哪一方、證詞、兩三個關鍵說法、帶出的證物 |
| 說法 | 一個關鍵說法 | 誰說、支持或削弱哪一環、會不會被剔除 |
| 理由 | 一組對照 | 說法 × 證物或另一個說法、批註文字、作用、哪一席才看得到 |
| 陪審員 | 一位陪審員 | 預設蓋章規則、翻不動的格子、跟大隊的程度、習慣、秘密 |
| 證據鏈 | 一個環 | 哪些說法支持它、是否必要 |

AI 陪審員的格子大部分由「預設蓋章規則」產生（例如「信警察」「只信物證」），只有關鍵的格子手寫。寫劇本的人填表，程式不用改。

## 3. 技術

- 舊 repo 的 Phaser 3 + TypeScript + Vite + Capacitor（iOS）骨架在歷史 `53ab3d3`，可以取回再用；分支對白用 inkjs（Ink 的 JS 版）。PC 優先的話，Godot 4 加 Ink 也合適。
- 規則（印章、黑板、表決）寫成不依賴框架的純邏輯。這樣可以用腳本跑上千場模擬評議來檢查平衡，例如第一天你的票是否真的是第五票。

## 4. 分期

| 階段 | 內容 |
|---|---|
| 0 原型 | 上面第 1 節 |
| 1 垂直切片 | 第七席完整一局：五天、視察現場、夜晚、約 10 個結局、像素美術初版 |
| 2 完整版 | 加 2–3 席（建議：馮國強、羅永昌、林曉晴） |
| 3 擴展 | 七席全開，加真結局 |

如果上手機：第一天本身就是最強的試玩，「一票之重」十多分鐘內就出現。可以免費開放第一天，再一次性解鎖完整審判。
